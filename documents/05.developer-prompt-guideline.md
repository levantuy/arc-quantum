# Hướng dẫn viết prompt cho nhà phát triển (Developer Prompt Guide)

## 1. Mục tiêu tài liệu
Tài liệu này giúp team viết prompt rõ ràng, đủ ngữ cảnh và kiểm soát chất lượng output khi làm việc với AI coding assistant trong dự án Arc Quantum.

Nguồn chuẩn hoá được rút từ các mẫu vai trò trong thư mục `agents/`:
- Vai trò rõ ràng (Role)
- Nhiệm vụ cốt lõi (Core task)
- Nguyên tắc làm việc (Working principles)
- Cấu trúc output (Output format)
- Giới hạn phạm vi (Scope limits)

## 2. Công thức prompt chuẩn cho Developer
Khi giao việc cho AI developer, luôn theo mẫu 8 phần sau:

1. **Role**: Xác định AI là Senior Developer/Tech Lead theo stack dự án.
2. **Task**: Nói rõ tính năng/module cần làm.
3. **Context**: Cung cấp UC/SRS/kiến trúc + đoạn code liên quan.
4. **Constraints**: Quy tắc coding, security, performance, scope.
5. **Output format**: Bắt buộc AI trả theo cấu trúc cụ thể.
6. **Acceptance criteria**: Điều kiện hoàn thành có thể kiểm chứng.
7. **Test requirement**: Unit/integration test cần có.
8. **Clarification rule**: Nếu thiếu dữ liệu thì hỏi trước khi code.

## 3. Prompt template (copy-paste)

```text
# VAI TRÒ
Bạn là Senior Software Developer / Tech Lead, viết code production-grade, clean, secure, testable.

# NHIỆM VỤ
Implement [TÊN FEATURE/MODULE] cho dự án Arc Quantum.

# NGỮ CẢNH DỰ ÁN
- Tech stack: Next.js (App Router) + TypeScript + Prisma + PostgreSQL
- Domain: DeFi bridge, wallet auth, admin configuration, audit logs
- Files liên quan:
  - [liệt kê file/folder]
- Requirements đầu vào:
  - [trích UC/SRS]
- Kiến trúc/convention:
  - [naming, lint, patterns]

# YÊU CẦU KỸ THUẬT
- Clean code, SOLID, không hardcode secret
- Validate input + xử lý lỗi đầy đủ
- Tối ưu truy vấn DB, tránh N+1
- Không thay đổi ngoài scope
- Nếu thiếu thông tin quan trọng: hỏi trước khi implement

# OUTPUT BẮT BUỘC
1. Implementation overview
2. Code theo từng file
3. DB schema/migration (nếu có)
4. API contract (nếu có)
5. Unit test + test cases chính
6. Cách chạy và cấu hình
7. Known limitations/TODO

# ACCEPTANCE CRITERIA
- [Tiêu chí 1]
- [Tiêu chí 2]
- [Tiêu chí 3]

# ƯU TIÊN
[Complete feature | API layer only | Skeleton]
```

## 4. Checklist chất lượng prompt trước khi gửi

- Đã nêu rõ output cần sửa ở file nào chưa?
- Đã có input requirements cụ thể (UC/SRS/flow) chưa?
- Đã nói rõ in-scope và out-of-scope chưa?
- Đã yêu cầu handling lỗi + validation + security chưa?
- Đã yêu cầu test cases/coverage chưa?
- Đã có tiêu chí nghiệm thu đo được chưa?
- Đã chỉ rõ mức độ ưu tiên (full feature hay skeleton) chưa?

## 5. Mẫu prompt tốt và chưa tốt

### Ví dụ chưa tốt
```text
Làm chức năng bridge token cho tôi.
```

Vấn đề:
- Không có scope rõ ràng
- Không có file context
- Không có acceptance criteria
- Không có yêu cầu test

### Ví dụ tốt
```text
Bạn là Senior Developer.
Implement API `POST /api/bridge/quote` để ước tính phí bridge.

Context:
- Dự án Arc Quantum, Next.js App Router, TypeScript, Prisma
- Dùng model `BridgeConfig` và `TokenConfig` hiện có
- File dự kiến cập nhật:
  - app/api/bridge/route.ts
  - lib/bridge/service.ts
  - lib/bridge/validator.ts

Yêu cầu:
- Validate chain/token/amount input
- Trả về cấu trúc `{ estimatedFee, etaSeconds, route }`
- Xử lý lỗi theo mã: `INVALID_INPUT`, `ROUTE_NOT_FOUND`, `INTERNAL_ERROR`
- Không sửa schema DB

Output:
1) Overview
2) Code diff theo file
3) Unit tests cho validator + service
4) Cách test local bằng curl

Acceptance criteria:
- Input sai trả 400 + INVALID_INPUT
- Không có route trả 404 + ROUTE_NOT_FOUND
- Case hợp lệ trả 200 và đầy đủ 3 field
```

## 6. Kỹ thuật giảm lỗi khi viết prompt

- **Chunking theo bước**: yêu cầu AI làm lần lượt API -> service -> test, không giao quá rộng trong 1 prompt.
- **Pin contract trước**: chốt request/response/error model trước khi code.
- **Nêu dữ liệu biên**: amount = 0, token không hỗ trợ, chain mismatch.
- **Ràng buộc side effects**: nói rõ không được đổi migration/schema nếu không yêu cầu.
- **Yêu cầu tự kiểm**: bắt buộc AI liệt kê assumptions trước khi implement.

## 7. Prompt mẫu theo từng loại việc developer thường làm

### A. Thêm API mới
```text
Implement endpoint [METHOD] [PATH] với input/output như sau [...].
Yêu cầu cập nhật validation, service layer, error mapping và unit tests.
Chỉ sửa các file: [...]. Không thay đổi DB schema.
```

### B. Refactor an toàn
```text
Refactor [module] để tách nhỏ hàm và tăng testability, không đổi hành vi runtime.
Yêu cầu: giữ nguyên API contract public, thêm test regression cho case chính.
```

### C. Tối ưu hiệu năng
```text
Tối ưu [query/flow] đang chậm.
Cần phân tích nguyên nhân, đề xuất fix, implement fix ít xâm lấn nhất, và chứng minh bằng before/after metrics ở local.
```

### D. Vá lỗi production
```text
Fix bug [mô tả lỗi].
Cung cấp: root-cause, patch tối thiểu, test tái hiện lỗi và test xác nhận đã fix.
Không refactor ngoài phạm vi bugfix.
```

## 8. Khung điền nhanh (1 phút)

Điền nhanh trước khi gửi prompt:

- Module: [...]
- User story / UC: [...]
- Files liên quan: [...]
- In-scope: [...]
- Out-of-scope: [...]
- API contract / expected behavior: [...]
- Error handling rules: [...]
- Tests bắt buộc: [...]
- Acceptance criteria: [...]

## 9. Kết luận
Prompt tốt cho developer không cần dài, nhưng phải rõ **vai trò + ngữ cảnh + ràng buộc + tiêu chí nghiệm thu**. Chỉ cần điền đúng template trong tài liệu này, chất lượng output sẽ ổn định hơn và giảm đáng kể vòng sửa lại.
